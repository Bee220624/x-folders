## 1. 产品定义

**一句话**：在 X 网页里给帖子加一套**本地文件夹收藏**：按主题归档、以后能快速找回、尽量不离开 X 页面。

**名称**：工作名称英文 *Folders for X*、中文「帖子文件夹」。名称只存在于语言文件里，上架前可以改，不影响代码。

**使用范围**：先自用（开发者模式加载），以后上架 Chrome 应用商店；本版本按「可上架」的标准做（双语、隐私政策、权限最小），但不提交商店。

**和 v0.1.0 工单相比的主要变化**：

1. 收藏列表里的卡片**尽量还原 X 的样子**（头像、图片、引用的帖子），不再只有文字；
2. 增加**关键词搜索**；
3. **两种阅读模式**（页面内 / 浏览器侧边栏），一键切换，默认页面内；
4. 页面内模式下，看完一条帖子按浏览器「返回」，能**回到刚才的列表位置**；
5. 增加**导出备份 / 导入恢复**；
6. **中英双语**，为上架做准备；
7. **真实浏览器验证成为硬门槛**（第 4 节）。

X 原生书签与本扩展完全独立：扩展不读取、不触发、不修改 X 原生书签。

## 2. 功能

### 2.1 保存帖子

- 每条能识别的帖子，操作栏里多一个「文件夹」按钮：有书签按钮时放在它后面，没有就放在最后。
- 按钮状态：
  - 没保存过：空心图标；
  - 已保存到至少一个文件夹：蓝色实心图标；
  - 鼠标悬停提示「保存到文件夹」或「已保存到 N 个文件夹」。
- 点按钮，弹出选择框：
  - 顶部「最近使用」，最多 3 个文件夹；
  - 下面是全部文件夹的树，这条帖子已经在里面的文件夹会打勾；
  - 点一个**没打勾**的文件夹：存进去，弹框关闭；
  - 点一个**已打勾**的文件夹：从这个文件夹移出，弹框关闭；
  - 底部「新建文件夹」：输入名字，建好后这条帖子自动存进去；
  - 按 Esc 或点弹框外面：关闭，焦点回到按钮。
- 点按钮不能触发帖子卡片的跳转，也不能触发 X 原生书签。
- 保存时把卡片需要的内容一并记下来（见 2.4 与 3.2）。
- 广告帖子不出现按钮。
- 同一条帖子可以放进多个文件夹；重复保存不会产生重复记录，也不改变第一次的保存时间。
- 两种阅读模式下，保存方式完全一样。

### 2.2 文件夹

- 两层：顶层文件夹 + 一层子文件夹；数据结构和树组件按递归写，不写死两层（层数上限由规则控制，超过时后台返回明确错误）。
- 新建、重命名（双击 / F2 / 右键菜单）、上移下移（同级）、折叠展开（会记住）、删除。
- 名称：去掉首尾空白后 1–64 个字符；同一父级下不能重名（不区分大小写）；不允许控制字符。
- 删除有内容的文件夹前先确认，写明会删掉几个子文件夹、几条收藏记录；同一条帖子在其他文件夹里的收藏不受影响。
- 每个文件夹旁边显示收藏数量。
- 以上功能在两种阅读模式里完全一样。

### 2.3 两种阅读模式

#### 页面内模式（默认）

- X 左侧导航栏里出现「我的收藏」文件夹树。
- 窗口太窄、X 左栏只剩图标时，改成一个文件夹图标，点开弹出文件夹树。
- 点一个文件夹：X 主栏上盖一层「收藏列表」。
  - 顶部：返回、文件夹名、收藏数量、搜索框、「切换阅读模式」按钮、「⋯」菜单（含「导出 / 导入」入口）；
  - 下面：帖子卡片，每次加载 50 条，滚到底自动加载更多。
- 点一张卡片：当前页面跳到原帖子，收藏列表关闭。跳转用 X 页面内的切换（像点 X 自己的链接一样），不整页重新加载。
- 看完按浏览器「返回」：收藏列表自动回来——还是刚才的文件夹、搜索词和滚动位置。
- 通过 X 自己的导航去了别的页面：收藏列表关闭，不会自动恢复。

#### 侧边栏模式

- 文件夹树、搜索框、收藏列表都放在 **Chrome 浏览器自带的侧边栏**里，和 X 页面并排。
- 侧边栏顶部：「切换阅读模式」按钮、「⋯」菜单（含「导出 / 导入」入口）。
- 点一张卡片：当前标签页是 X，就让它跳到原帖子（同样用 X 页面内的切换，不整页重新加载），**侧边栏不动**，可以一条接一条地看；当前标签页不是 X，就在新标签页打开。
- 这个模式下，X 左侧导航里只保留一个小的「我的收藏」图标，点它打开侧边栏；浏览器工具栏上的扩展图标也能打开。
- 用侧边栏自带的 × 关闭侧边栏后，仍然是侧边栏模式；用上面两个入口可以重新打开。

#### 切换

- 收藏列表顶部、侧边栏顶部各有一个「切换阅读模式」按钮，这是切回页面内模式的唯一方式。
- 页面内模式下点浏览器工具栏图标 = 切换到侧边栏模式。
- 切换时带上当前的文件夹和搜索词：从页面内切到侧边栏，覆盖层关闭、侧边栏打开；从侧边栏切回，侧边栏关闭、当前 X 页面打开收藏列表。
- 会记住你的选择，下次沿用；新安装时默认页面内模式。

### 2.4 帖子卡片（尽量还原 X）

- 显示内容：
  - 头像、昵称、认证标记、@用户名、发帖时间；
  - 正文：保留换行，链接、@提及、#话题 高亮且可以点；
  - 图片：1–4 张，按 X 的方式排列；
  - 视频和 GIF：显示封面加播放标记；卡片内不播放，点它打开原帖，由 X 自己的播放器播放；
  - 引用的帖子：作者、正文、第一张图；
  - 链接预览卡片：标题、域名、图片。
- 不显示点赞、转帖、回复数（这些数字会过时）。
- 卡片底部：「保存于 某日」，以及一个「⋯」菜单（从此文件夹移除、在新标签页打开）。
- 点卡片打开原帖（按 2.3 的规则）；按住 ⌘（Windows 上是 Ctrl）再点，在新标签页打开。
- **只记图片地址，不下载图片**：原帖被删后，文字和作者还在，图片可能变成灰色占位。
- 时间线上被「显示更多」截断的长帖：先存看得到的部分；以后在帖子详情页等地方看到完整内容时，自动补全。
- 已补全的长帖在卡片里像 X 一样先折叠成几行，点「显示更多」在卡片内展开，不跳转；还没补全的，点「显示更多」打开原帖。
- 移除后卡片立即从列表消失、数量更新；帖子不再属于任何文件夹时，其内容记录在后台清理。
- 空文件夹、加载中、出错都有明确的提示。
- 某文件夹在别的标签页被删除时，正在看它的列表自动关闭或显示「已删除」。

### 2.5 搜索

- 两种模式的收藏列表顶部都有搜索框。
- 搜索范围：正文、昵称、@用户名、引用帖子的正文。
  - 不区分大小写；中文直接按字匹配；
  - 空格隔开多个词，表示每个词都要包含。
- 打开某个文件夹时，默认只搜这个文件夹，一键切到「全部收藏」。
- 结果按保存时间从新到旧排列，并标出每条在哪些文件夹里。

### 2.6 导出与导入

- **导出**：菜单里点「导出备份」，下载一个备份文件（JSON 格式），包含全部文件夹、帖子内容、归属关系和最近使用记录。
- **导入**：选择备份文件 → 先检查文件是否有效 → **合并**进现有数据：
  - 不会覆盖或删除已有内容；
  - 同一个文件导入两次，也不会产生重复。
- 重装扩展后，把备份导入到空的扩展里，就等于恢复。

### 2.7 其他

- **实时同步**：多个 X 标签页、侧边栏之间，任何一处的改动，其他地方马上更新。
- **主题**：自动适配 X 的「默认 / 暗淡 / 熄灯」三种背景；侧边栏跟随 X 最近一次的背景。
- **语言**：中文 / 英文，跟随浏览器语言（浏览器是简体中文时显示中文，否则英文）。
- **账号**：数据按浏览器共用，不区分 X 账号。
- **防丢数据**：开发版固定扩展 ID，避免从不同目录重新加载后数据「消失」；README 提醒：数据只在本机，卸载扩展会删除全部收藏，建议定期导出。

### 2.8 这一版不做

- 云同步、多设备同步；
- AI 自动分类、标签；
- 导入 X 原生书签；
- 调用 X 的任何接口；
- 下载图片、视频文件，保存网页快照；
- 拖拽排序、超过两层的文件夹；
- 按 X 账号分开存数据；
- 手机网页版、X App、嵌入式帖子；
- Firefox / Safari 正式支持（但架构上不堵死）；
- 在收藏列表里点赞、转帖、回复；
- 任何统计、数据上报。

不得以「顺手做了」为理由加入这些功能。

## 3. 技术方案

> 本节只规定**结果、约束和验收方法**，不规定每个细节怎么写。

### 3.1 总体结构

扩展运行在三个地方：

| 运行位置 | 负责什么 | 能不能碰数据库 |
|---|---|---|
| **后台**（Service Worker） | 唯一的数据库写入者；处理所有读写请求；负责打开侧边栏；通知各处刷新 | 能，且只有它能写 |
| **X 页面里**（内容脚本） | 识别帖子、提取内容、注入文件夹按钮；保存弹层；页面内模式的左栏文件夹树和收藏列表 | 不能，只能发请求给后台 |
| **扩展自己的页面**（侧边栏、数据管理页） | 侧边栏模式的树 / 搜索 / 列表；导出导入 | 不能直接写，同样发请求给后台 |

- **技术栈**：沿用 v0.1.0 的 WXT + TypeScript（严格模式，不用 `any`）+ Preact + Dexie（IndexedDB）+ Floating UI + Vitest + pnpm；新增 Playwright 做真浏览器端到端测试。代码审查中如发现某项不合适，在审查结论里提出，经确认后替换。
- **界面组件只写一套**：文件夹树、帖子卡片、搜索框、列表、确认框、提示条，同一套组件既能挂进 X 页面（放在封闭的 Shadow DOM 里，样式不外泄），也能挂进侧边栏。样式也只有一份。
- **帖子按钮**用轻量原生 DOM 实现，不为每条帖子创建一个框架实例。
- **所有请求走同一套带类型、带运行时校验的接口**，后台不信任任何传进来的数据；错误转换为稳定的错误码，界面给出能看懂的提示，不泄露堆栈。
- **变更通知**：后台每次写完数据，写一条很小的变更记录到扩展存储，所有 X 标签页、侧边栏据此只刷新受影响的部分。
- **阅读模式偏好**也存在扩展存储里，任何一处切换，各处立即生效。
- 后台随时可能被浏览器回收：不在内存里保存任何业务状态，每个请求都能独立完成。
- 单个文件建议不超过约 500 行；不允许出现包揽一切的巨型类。

### 3.2 数据

#### 存什么

沿用 v0.1.0 的「文件夹 / 归属关系 / 最近使用」三块（代码审查确认可用后保留）。「帖子」这块从「只有文字」升级为**快照**：

| 字段 | 内容 |
|---|---|
| 帖子 ID、永久链接 | ID 必须是数字串；链接统一成 `https://x.com/用户名/status/ID` |
| 作者 | 昵称、@用户名（以链接为准）、头像地址、是否认证 |
| 发帖时间 | 取自页面上的时间标签 |
| 正文 | 纯文本（用于搜索，上限 50,000 字符）+ 结构化片段（普通文字 / 链接 / @提及 / #话题 / 表情），**不存 HTML** |
| 媒体 | 每张图 / 视频封面 / GIF 封面的**地址**和类型，不下载文件 |
| 引用的帖子 | 作者、正文、第一张图、链接 |
| 链接预览卡片 | 标题、域名、图片地址、链接 |
| 是否被截断 | 时间线上有「显示更多」时为是，之后看到完整内容时补全 |
| 首次保存 / 最近更新时间 | 本机时间 |

- 归属关系记录「哪个文件夹、哪条帖子、保存时间」；保存时间属于归属关系，写入后不再修改。
- 地址白名单：图片只接受 X 的图片服务器（`https://pbs.twimg.com/`）；链接只接受 `https` / `http`；其他一律丢弃。
- 数据库版本升级时要写迁移（v0.1.0 的旧格式能自动升级），为上架后的版本更新打基础。
- 以下操作必须在一个数据库事务里完成：保存到文件夹、从文件夹移除（含清理不再属于任何文件夹的帖子）、删除文件夹（含子文件夹、归属关系、最近使用、孤立帖子）、导入。

#### 搜索

- 由后台执行；支持「当前文件夹」和「全部收藏」两种范围。
- 实现方式（例如维护一份精简的搜索文本表）由实现者决定，但要满足 4.2 的性能指标并有测试证明。

#### 导出与导入

- 备份文件是带格式名和版本号的 JSON。
- 导入把文件当**不可信输入**：逐字段校验、大小上限、地址白名单；任何一条不合格就整体拒绝并说明原因。
- 合并规则：
  - 同一父级下同名文件夹合并为一个；
  - 同一条帖子取信息更全的那份（优先未截断的，其次最近更新的）；
  - 归属关系取并集，保留最早的保存时间；
  - 导入两次结果不变。
- 导出、导入在「数据管理页」（扩展的选项页）里完成，不需要下载权限。两种模式的「⋯」菜单都能跳到这个页面。

### 3.3 与 X 页面打交道的规则

1. **所有 X 选择器集中在一个文件**，任何其他地方不许直接写选择器；只用 `data-testid`、`role` 这类稳定属性，不用 X 的混淆类名、不用深层位置路径、不用会随语言变化的文字。
2. **先抓真实页面再写代码**：从真实 x.com 抓取并脱敏的页面样本（首页宽屏 / 窄屏、详情页、个人主页、搜索、书签页，覆盖引用帖、1–4 图、视频、GIF、链接卡片、长帖、广告）是所有提取与注入测试的依据。脱敏采用「默认替换、只放行结构性内容」，提交前复查不含真实用户名、帖子 ID、token、cookie。
3. **键盘隔离**：插件的任何输入框里打字，按键都不能传到 X（否则会触发 X 的快捷键，例如点赞、翻页）。
4. **不挤坏 X 的布局**：左栏文件夹树高度动态计算，任何窗口高度下都不能把账号切换按钮挤出屏幕；X 自己的元素位置和可点击性不受影响。
5. **不挡 X 的弹层**：收藏列表覆盖层打开时，X 的菜单、图片查看器、提示仍然显示在它上面。
6. **自愈且不重复**：X 重建页面、切换页面、虚拟列表复用节点后，按钮、文件夹树、覆盖层自动恢复并显示正确状态；任何时候都不出现重复。
7. **不拖慢 X**：不在每次页面变化时扫描整页；大量新帖子分批处理。
8. **干净退出**：扩展被重新加载、停用或卸载后，X 页面上不留任何插件元素和后台任务。
9. 插件的所有页面元素用 `data-xf-*` 属性标识。

### 3.4 两种阅读模式的实现要点

- **打开侧边栏**有两个入口：浏览器工具栏图标、X 页面里的入口 / 切换按钮。后者要求「在页面里点击 → 后台立即打开侧边栏」。这一条依赖 Chrome 的规则，**第 5 节第 1 步就要在真实 Chrome 里验证**；如果不可行，退化为提示「点工具栏图标打开」，并回来跟用户确认。
- **侧边栏里点卡片**：判断当前标签页是不是 X，不能依赖额外的敏感权限（例如向该标签页的内容脚本询问）。
- **页面内模式的「返回恢复」**：点卡片跳走前记下文件夹、搜索词、滚动位置；浏览器返回到原页面时，自动重新打开列表并恢复。这些状态只存在浏览器会话里，关闭浏览器即清除；跳转可能是整页加载，恢复逻辑不能依赖内容脚本的内存。
- **切换模式**：按 2.3「切换」的规则执行。

### 3.5 权限与隐私

- 只申请：`storage`、`unlimitedStorage`、`sidePanel`；内容脚本只在 `https://x.com/*`、`https://twitter.com/*` 运行。如确有必要，可以对这两个网站加同名的站点权限（安装时不会多出新的警告）。
- **不申请**：`tabs`、`downloads`、`cookies`、`webRequest`、`declarativeNetRequest`、`scripting`、`history`、`identity`、所有网站权限（`<all_urls>`）。
- 不调用 X 的任何接口，扩展代码不发起任何网络请求；唯一的网络活动是显示卡片时从 X 的图片服务器加载头像和图片（和正常浏览 X 一样），隐私说明里写明。
- 没有远程代码、没有统计上报。
- 正文用结构化片段渲染，不拼 HTML；插件界面放在封闭的 Shadow DOM 里，X 页面上的脚本读不到用户的文件夹和收藏。
- 隐私说明（中英文）写清：存了什么、没存什么、存在哪、怎么删、图片从哪加载、受保护账号的帖子同样以明文存在本机。

### 3.6 构建与交付

- `pnpm build` 输出到**看得见的** `dist/chrome-mv3/`，安装时直接选这个文件夹；`pnpm zip` 生成上架用的压缩包。
- 开发版固定扩展 ID（在清单里写公钥）；上架包不带这个字段，由商店分配 ID。
- 语言文件：中文、英文两份，默认英文。
- 上架准备（这一版做好，不提交）：中英文名称与简介、图标、5 张截图（用脱敏样本生成，不出现真实账号）、隐私政策页、权限用途说明。
- 文档：README（安装、开发、使用、数据风险提示）、架构说明、选择器维护手册、隐私说明、手工验收记录、CHANGELOG、许可证（保留 MIT）。

## 附录：已知事实（写代码前必读）

### A. X 页面（2026-09-03 与 2026-09-28 在真实登录态下实测）

1. 帖子根节点是 `article[data-testid="tweet"]`，时间线的每一行是 `[data-testid="cellInnerDiv"]`。
2. **引用的帖子不是嵌套的帖子根**，而是同一个 `article` 里的 `div[role="link"][tabindex="0"]`，自带作者、时间和正文。2026-09-29 实测其中**没有指向引用帖的链接**（时间在普通 `div` 里），所以快照里引用帖的链接只在页面给出时才有。
3. **详情页主帖的头部没有 `<time>`**，时间在正文下方单独的永久链接行里；该帖还有 `/analytics`、`/quotes` 两个干扰链接，只有真正的永久链接里有 `<time>`。
4. 链接是相对路径，要读 `a.href` 属性拿到完整地址。
5. **操作栏里有没有书签按钮会变**：09-03 在首页实测没有（书签收进了分享菜单）；09-28 在约 1400px 宽的窗口实测有（回复 / 转帖 / 喜欢 / 查看 / 书签 / 分享）。
6. 不存在 `[data-testid="AppTabBar"]` 这个容器，只有逐项的 `AppTabBar_*_Link`；导航根用 `header[role="banner"] nav`。
7. 左栏那一列 = 导航与账号切换按钮（`SideNav_AccountSwitcher_Button`）的最近公共祖先；插入点在账号切换块之前。
8. X 的所有弹层都在 `#layers` 里，而它的层级（z-index）只有 1：覆盖层必须放在它之前、层级保持很小。
9. 主题只有 `<body>` 的内联背景色可靠：默认 `rgb(255,255,255)`、暗淡 `rgb(21,32,43)`、熄灯 `rgb(0,0,0)`（后两个尚未实测）。
10. 广告帖带 `[data-testid="placementTracking"]`，而且常常没有永久链接。
11. X 有全局键盘快捷键；Shadow DOM 里的按键会冒泡到页面，必须拦截。
12. **链接卡片**：小卡片的域名、标题、描述在卡片内部；大卡片内部只有图片和标题，域名印在卡片下方的另一个链接里（2026-10-01 实测）。
13. **广告帖没有 `<time>`**；`placementTracking` 也会出现在普通视频帖内部，广告帖上则可能挂在帖子外层（2026-09-30 样本）。
14. **x.com 页面上的 `<a>` 点击会被 X 自己的链接处理接管**；`history.pushState` 加一次 `popstate` 事件能让 X 在页面内切换路由，不整页重新加载（2026-09-30 抓样本时实测）。

### B. Chrome 扩展平台

1. 按网址查找标签页需要 `tabs` 权限或站点权限，内容脚本的匹配规则不算 → 不要靠「查找所有 X 标签页再群发」做同步。
2. 后台的消息监听器必须在启动时同步注册；需要异步回复时必须同步返回 `true`。
3. 后台闲置约 30 秒会被浏览器回收，不能把任何业务状态只放在内存里。
4. 数据库事务里不能等待数据库以外的异步操作，否则事务会提前提交。
5. IndexedDB 不能给 `null` 建索引 → 不要给「父文件夹 ID」建索引（根文件夹的父级是 `null`）。
6. Google Chrome 137 起不再支持命令行加载扩展 → 自动化端到端测试用 Chromium。
7. WXT 默认会把内容脚本的 CSS 注入到 x.com 页面里 → 必须改为只注入到自己的 Shadow DOM。
